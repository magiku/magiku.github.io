C08【B站优化】为B站的网页全屏模式增加一个侧边评论区

发表于2026-09-03|更新于2026-09-03|折腾/运维案例

前言

刷B站时，有些视频就想边放边看看评论区。往下滑到评论区，视频会以画中画的形式显示，但太小了，也看不了弹幕。

于是我想到，模仿油管，在全屏模式下放置一个按钮可以呼出评论区，显示在右侧。

实现的效果如下：

这个功能只在网页全屏和完全全屏下显示，点击按钮启用，再次点击恢复原样；视频与评论区之间可以拖拽，随时调整两者的屏占比。

默认状态和宽屏模式完全不干预，不影响正常体验。

安装

前提-安装油猴插件

以Windows自带的Edge浏览器为例：

在浏览器右上角点击扩展按钮，选择菜单里的[ 获取Microsoft Edge扩展 ]，然后搜索“篡改猴”，点击获取安装。

安装脚本

方法一：从脚本仓库安装

脚本文件我已经上传到了GreasyFork (油叉)，可以在上面找到B站网页全屏模式显示评论区（播放器下方按钮点击启用），点击安装即可。

如果网络问题无法打开该网站，那么就可以尝试方法二。

方案二：自定义脚本

在右上角找到油猴的图标，点击弹出菜单，再点击添加新脚本。

在弹出的脚本编辑页面，全选删除，再把上面这段脚本代码复制进去，按Ctrl+s进行保存即可。

原理介绍

核心功能

  1. 视频画面左移，宽度被压缩。
  2. 评论区嵌入播放器右侧，默认35%的宽度，样式完全沿用B站自带。
  3. 中间有可拖拽的分隔条：拖动即可实时调整视频与评论区的屏占比（默认范围 15%~70%），松手后自动记住，下次打开还是这个比例。分隔条平时完全隐形，鼠标移上去或拖拽时才显出一条贯穿上下的细线，不干扰观看。
  4. 评论区会强制重载，确保内容正常显示。
    再次点击按钮，评论区恢复原位，视频恢复全宽。
  5. 切换视频/分集时评论区自动跟随：只把评论组件指向新视频并重载，不刷新整个网页、不中断播放。
  6. 网页全屏与完全全屏都支持，两者互切时侧栏不会丢失；默认状态和宽屏模式完全不干预。

可修改内容

默认评论区占比为35%，这个值只是初始值——拖拽分隔条即可随时调整，范围默认 15%~70%，松手后会记住。想改初始值或范围，修改代码中的这几个配置即可：

默认同时支持网页全屏（web）和完全全屏（full），如果只想保留其中一种，可修改 fullscreenScreens：

另外，B站评论组件在被搬动或重建时，会向控制台抛出一条没有任何信息的报错（Uncaught (in promise) undefined），这是组件自身的缺陷——不装本脚本，单纯切换分集时同样会出现。脚本默认把自己搬运评论区所引发的那条静默掉（只静默“搬运前后 3 秒内 + 报错信息为空”的定向场景）；如果你更希望看到页面的原始报错，可以把 suppressMoveNoise 改为 false。

代码逻辑

1. 全屏状态的精准捕获（触发条件）

B站播放器的模式由 .bpx-player-container 的 data-screen 属性标识：normal（默认）→ wide（宽屏）→ web（网页全屏）→ full（完全全屏）。脚本以它作为唯一判据，支持哪些模式由 fullscreenScreens 决定：

  • 监听 data-screen 变化：用 MutationObserver 直接盯住该属性，模式一变立刻响应。
  • 监听标准全屏API：监听 fullscreenchange 等事件——完全全屏会额外触发浏览器的 Fullscreen API。
  • 兜底轮询（Polling）：每 500ms 执行一次 onFullscreenChange 检查，防止播放器容器晚于脚本渲染。
    • 进入 web/full 时创建按钮；两者互切时不重建嵌入状态（用 activeScreen 记录当前模式），评论区不会被搬来搬去。
    • 退出到 normal/wide 时用 300ms 延迟定时器确认后再退出，容忍模式切换过程中的瞬时中间态；确认真的退出了，才销毁按钮并恢复评论区位置。

2. 评论区的“搬运”与布局重置（核心交互）

点击按钮触发 toggleEmbed，执行 doEmbed 函数：

  • 保存现场：搬运前保存评论区的 parentNode 和 nextSibling，并把要改动的元素原样式逐项记下来（rememberStyle），恢复时精确还原。
  • 创建容器：动态生成一个 div#embedded-comment-container，只负责“占位 + 滚动”；背景取B站主题变量 var(--bg1, #fff)（浅色为白、深色自动跟随），顶部留 10px 间距，评论区内容一律沿用B站自带样式。
  • Flex布局改造：把布局根（.bpx-player-container）设为 display: flex + flex-direction: row，视频区（.bpx-player-primary-area）与评论容器左右并排（默认 65% / 35%，可拖拽调整）。完全全屏时 .bpx-player-container 本身就是浏览器的全屏元素，所以两种模式共用同一套布局，互切不会失效。
  • 可拖拽分隔条：在视频区和评论容器之间插入一个 6px 宽的分隔条（热区），用 pointerdown + setPointerCapture 接管拖拽，实时把新占比写回两侧的 flex-basis。分隔条本体取评论面板同色（var(--bg1, #fff)）打底，既挡住视频元素从下方透出，又让分隔区域在默认状态下与评论区融为一体；内部只有一条 2px 的竖线握把，默认 opacity: 0 不显示，鼠标悬停或拖拽时才淡入，并贯穿容器顶部到底部。握把用 justify-content: flex-start 贴在分隔条左边缘（也就是紧贴视频画面），所以从左到右是「黑视频 → 灰握把 → 白评论」的自然过渡；若让它居中，握把左侧会夹出一条 2px 白缝，在黑色视频背景上很显眼。宽度写成 calc((100% - 6px) * 占比)，所以两侧加上分隔条永远正好等于容器宽度，窗口缩放也会自动跟随；占比限制在 15%~70%，松手后写入 localStorage，下次进入沿用。
  • 截断滚轮冒泡：播放器把“滚轮调音量”的监听挂在 document 和播放器根节点上（都在冒泡阶段），而侧栏就在播放器容器内部，滚轮冒泡上去会误触音量。于是在容器上就地 stopPropagation()，wheel/mousewheel/DOMMouseScroll 三种事件名都拦。只截断冒泡、不 preventDefault，所以侧栏自身的滚动照常，播放器区域的滚轮调音量也不受影响。
  • 强制重载评论：找到评论组件（bili-comments），移除并重新添加 lazy-load 属性，并调用其内部的 reload() 方法，避免评论因DOM迁移而加载失败。

3. 评论按钮的注入（UI入口）

脚本会定位播放器控制栏的右侧区域（.bpx-player-control-bottom-right），在 【字幕】和【音量】两个按钮之间 插入一个自定义的 div 按钮，内嵌一个对话气泡样式的SVG图标。点击该按钮即执行切换逻辑。

4. 切换视频时评论区如何跟随（SPA特性）

B站视频页面是单页应用（SPA），切换视频（合集分集、右侧推荐等）走的是 history.pushState/replaceState，不会触发 popstate，也不会刷新页面。结果是播放器换成了新视频，而评论组件的 data-params（值为 "1,<aid>"，决定加载哪个视频的评论）还停留在旧视频上。

老版本的做法是“发现URL变了就 location.reload()”，简单但粗暴：整页重建、播放中断。新版本直接去拧那个开关：

  • 捕获导航：给 history.pushState/replaceState 打补丁，并监听 popstate；再用 500ms 轮询比对URL里的 BV号 兜底，防止漏掉某种导航方式。
  • 取当前视频的 aid：从 window.__INITIAL_STATE__.aid 读取。
  • 同步并重载：把评论组件的 data-params 写成 "1," + aid，再调用 reload()。评论区原地换成新视频的评论，页面不刷新、播放不中断。

附注：B站的评论区目前有两套实现——现代组件 bili-comments（带 shadowRoot）和一套旧版 DOM。本脚本针对的是前者，也就是你现在在B站上实际看到的那一套。

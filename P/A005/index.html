A005【项目管理】软考中项-项目管理图表速查手册

发表于2026-07-22|更新于2026-10-22|项目管理

一、总览：图表的六种分类

本文将软考中项涉及的图表和图形工具分为六类：结构分解、进度时间、成本资金、质量分析、风险决策、人员与沟通。

类别 核心问题 代表图表 主要知识领域
结构分解类 项目由什么组成？谁来做？ WBS、OBS、RBS、RAM/RACI、需求跟踪矩阵 范围、资源、沟通
时间进度类 什么时候做？先后顺序？ 甘特图、里程碑图、单/双代号网络图、时标网络图、资源直方图 进度
成本资金类 花多少钱？花到哪一步了？ S 曲线、挣值分析曲线、资金需求曲线 成本
质量分析类 问题出在哪？是否受控？ 老七种工具、新七种工具、质量屋 质量
风险决策类 有什么风险？选哪个方案？ 风险分解结构、概率影响矩阵、决策树、龙卷风图、蒙特卡洛、影响图 风险
人与沟通类 谁会支持/阻碍？怎么沟通？ 权力/利益方格、干系人参与评估矩阵、沟通模型、沟通渠道公式 干系人、沟通

题干关键词对照
“分解到工作包”→ WBS；“显示活动先后依赖”→ 网络图；“横道图/直观显示工期”→ 甘特图；“找主要原因”→ 帕累托图；“找根本原因”→ 因果图；“判断过程是否稳定”→ 控制图；“两个变量是否相关”→ 散点图；“定量分析风险、算期望值”→ 决策树。

二、范围与结构分解类

这类工具用于分解项目范围、组织资源并明确责任。WBS 关注交付成果，OBS 关注组织单元，RAM 则把工作与责任对应起来。

1. WBS 工作分解结构（Work Breakdown Structure）★★★

WBS 按可交付成果逐层分解项目范围，直到形成可管理的工作单元，最底层通常是工作包。它为后续的工作估算、进度安排和责任分配提供依据。

图：WBS 层级结构——第 2 层是控制账户，第 3 层是工作包或规划包

  • 分解原则：面向可交付成果而非活动；遵循 100% 原则（子层之和必须完整等于父层，不多不少）。
  • 分解粒度：工作包一般分解到 8～80 小时（约 1～2 周内可完成），便于估算与考核。
  • 未纳入 WBS 的工作不属于已定义的项目范围。新增工作应经过范围变更控制，避免范围无序扩张。
  • 表现形式：树形图（用于汇报展示）、列表/缩进式（用于大型项目，容量大）、组织图式。
  • 配套文件：WBS 词典（逐个说明工作包的内容、责任人、里程碑、成本、验收标准）。
  • WBS + WBS 词典 + 项目范围说明书 = 范围基准。

考点

  • WBS 面向可交付成果。遇到“按阶段分解”或“按职能分解”等表述时，应结合具体内容判断是否符合成果导向。
  • 100% 原则、8/80 小时法则、工作包定义，是选择题常客。
  • WBS 是估算活动、估算成本、制定进度计划、识别风险的共同输入。

2. OBS 组织分解结构（Organizational Breakdown Structure）★★

OBS 按项目中的组织部门或团队逐层分解，显示各组织单元的层级与构成。将 OBS 与 WBS 对照，可以形成责任分配矩阵。

图：OBS 按组织部门分解，与 WBS 交叉得到责任分配矩阵

  • WBS 回答“要做什么”，OBS 回答“谁来做”。
  • WBS 与 OBS 交叉形成的矩阵即 RAM（责任分配矩阵），交叉点是“组织单元对工作包负责”。
  • 常用于大型项目、多部门协同项目，便于把工作包落实到部门。

3. RAM / RACI 责任分配矩阵（Responsibility Assignment Matrix）★★★

RAM 将 WBS 中的工作包与团队成员或部门交叉排列，用符号标明各方承担的角色。RACI 是常见的四角色模型。

图：RACI 矩阵，每行只有一个 A

字母 英文 中文 含义 数量要求
R Responsible 执行者 实际动手完成工作的人 可多人
A Accountable 负责人 / 问责人 对结果最终负责、有批准权的人 有且仅有 1 人
C Consult 咨询者 提供意见、需双向沟通的人 可多人
I Inform 知会者 需被通知结果、单向沟通的人 可多人
  • 作用：明确职责、避免推诿；也是规划资源管理过程的核心工具。
  • 小项目可用“责任人 + 支持者”的简化矩阵；大项目用 RACI 全模型。

考点
每项活动只能有一个 A（问责人）。A 可以同时承担 R，也可以只负责最终问责。若出现职责不清或无人负责的情况，可检查责任分配矩阵。

4. 需求跟踪矩阵（Requirements Traceability Matrix, RTM）★★★

需求跟踪矩阵将每条需求与其来源，以及后续的设计、开发和测试用例关联起来，支持正向和反向追溯。

图：需求跟踪矩阵的双向追溯

  • 正向追溯：需求 → 设计 → 代码 → 测试，确保需求都被实现。
  • 反向追溯：从交付成果回溯到需求，确保没有“多余的功能”（防范围蔓延）。
  • 典型列：需求编号、需求描述、来源、优先级、设计文档号、测试用例号、状态。
  • 作用：确保每个需求都有价值来源，且都被交付和验证；是确认范围、控制质量的重要依据。

考点
需求跟踪矩阵属于规划范围管理的工具产物，用于“确保需求被满足、防止遗漏和镀金”。看到“需求—测试用例对应关系”就选它。

5. RBS 资源分解结构（Resource Breakdown Structure）★★

RBS 按资源类别与类型逐层整理项目所需资源，例如人力、设备、材料和软件许可，可用于资源估算与成本汇总。

图：资源分解结构，按资源类别逐层分解

考点 · 易混
软考中有两个 RBS：

  • 资源分解结构（Resource BS）——属于资源/成本管理，分解“资源类别”。
  • 风险分解结构（Risk BS）——属于风险管理，分解“风险来源类别”。

题干出现“按资源类别分解”选前者，“按风险来源分解”选后者。

三、进度与时间类

进度管理常用甘特图和里程碑图展示计划，也用网络图表达活动依赖关系并计算关键路径。涉及工期、浮动时间和关键路径的计算题，通常需要网络图。

6. 甘特图 / 横道图（Gantt Chart）★★★

甘特图以时间为横轴、活动为纵轴，用横向条形表示活动的起止时间和持续时间，适合查看整体安排及计划与实际进度的差异。

图：甘特图，条形长度 = 持续时间，位置 = 起止时间

  • 优点：直观易懂、便于向管理层和客户汇报进度、易看出进度偏差。
  • 缺点：默认不能清晰表达活动之间的逻辑依赖关系，也看不出关键路径（加连接线可部分弥补，但不如网络图严谨）。
  • 可用于制定进度计划和控制进度（用“跟踪甘特图”对比计划与实际两条横道）。

考点
常见考法是询问甘特图的局限：它通常无法清晰呈现活动之间的依赖关系和关键路径。展示起止时间、持续时间及进度偏差，则是甘特图的主要用途。

7. 里程碑图 / 里程碑清单（Milestone Chart）★★

里程碑图列出项目中的关键节点及其计划日期，例如主要交付成果完成或重要阶段结束的时间。它不展示各项活动的持续时间。

图：里程碑图，菱形是时间点，工期为 0

  • 里程碑持续时间为 0，只是一个时间点、一个检查点。
  • 用于向高层管理者或客户汇报“关键节点是否达成”，是甘特图的简化版。
  • 里程碑清单是定义活动过程的输出，属于进度基准的一部分。

考点
里程碑的工期为 0；里程碑不消耗资源（除检查活动外）。“里程碑图用于向高层汇报”是常见正确选项。

8. 单代号网络图（PDM / AON）★★★

节点代表活动（Activity-on-Node），箭线只表示逻辑依赖关系。软考计算题默认用这种图，因为可以直接在节点上标注六个时间参数。

图：单代号网络图，节点=活动，箭线=依赖关系

  • 四种依赖：FS（完成—开始，最常用）、SS（开始—开始）、FF（完成—完成）、SF（开始—完成）。
  • 六参数：ES 最早开始、EF 最早完成、LS 最迟开始、LF 最迟完成、TF 总浮动时间、FF 自由浮动时间。
  • 关键路径：从起点到终点持续时间最长的路径，其总浮动时间 = 0；关键路径上的活动即关键活动。
  • 总浮动时间 TF = LS − ES = LF − EF；自由浮动时间 = min(紧后活动 ES) − 本活动 EF。
  • 关键路径可能不止一条；项目延期后关键路径可能发生转移。

考点

  • 网络图常用于计算项目工期、关键路径和活动的总浮动时间。
  • “总浮动时间为负”表示进度已落后于计划，需要压缩工期。
  • 压缩工期优先压缩关键活动，且选“赶工成本最低”的；压缩到出现新的关键路径时要停止或同步压缩。

9. 双代号网络图（ADM / AOA）★★

箭线代表活动，节点只代表“事件”（活动的开始或结束时刻）。因为箭线只能表示 FS 关系，遇到交叉依赖时必须引入虚活动（虚箭线，工期 0、不消耗资源）。

图：双代号网络图，虚线箭头是虚活动

  • 特点：只能表达 FS 依赖，需要虚活动处理复杂逻辑，绘图比单代号繁琐。
  • 优点：便于用“节点最早/最迟时间”做时间参数计算，早期网络计划常用。
  • 识别要点：图上出现虚线箭头，基本就是双代号网络图。

考点
虚活动的工期为 0、不消耗资源，作用是“正确表达逻辑关系”。判断题常设“虚活动需要消耗时间”这样的错误选项。

10. 时标网络图（Time-Scaled Network Diagram）★★

时标网络图在网络图中加入时间刻度。箭线的水平投影长度表示活动持续时间，波形线表示自由浮动时间。

图：时标网络图，波形线表示自由浮动时间

  • 兼具网络图（逻辑关系）与甘特图（时间直观）的优点。
  • 看图技巧：没有波形线的路径就是关键路径；波形线长度 = 该活动的自由浮动时间。
  • 是“进度计划”的常用表现形式之一，也便于做资源均衡分析。

11. 资源直方图（Resource Histogram）★★

资源直方图以时间为横轴，用柱形表示各时间段所需的资源数量，可用于识别资源超配，并辅助安排资源。

图：资源直方图，柱高超过上限即资源冲突

  • 柱高超过资源可用上限 → 资源冲突，需资源平滑（不改变关键路径、不延长工期，只在浮动时间内调整）或资源平衡（可能延长工期）。
  • 与“资源分解结构 RBS”配合使用：RBS 说明资源类别，直方图说明资源随时间的分布。

考点
资源平滑：不改变关键路径、不推迟项目完工日期，只在浮动时间内调整，可能无法满足全部资源需求。
资源平衡：为在资源供需间取得平衡，往往会改变关键路径、延长工期。这一对概念在三批真题里都出现过。

四、成本与资金类

成本管理中常见的图表包括 S 曲线和挣值分析曲线。S 曲线展示累计成本基准随时间的变化，挣值曲线用于比较计划值、挣值和实际成本。

12. S 曲线 / 成本基准曲线（S-Curve）★★★

S 曲线以时间为横轴、累计成本为纵轴，通常呈现前期增长较慢、中期增长较快、后期逐渐放缓的形态。成本基准可按时间分配并累计后绘制成曲线。

图：S 曲线，累计成本随时间呈 S 形增长

  • 成本基准 = 经批准的、按时间段分配的预算，不含管理储备。
  • 项目总预算 = 成本基准 + 管理储备。管理储备用于“未知—未知”风险，动用需高层批准，动用后成本基准变更。
  • 应急储备包含在成本基准内，用于“已知—未知”风险，由项目经理直接动用。

考点

  • 成本基准不含管理储备；总预算含管理储备。这是超高频陷阱。
  • 应急储备在基准内、项目经理可动；管理储备在基准外、需高层批准。

13. 挣值分析曲线（Earned Value Analysis）★★★

挣值分析曲线将 PV（计划值）、EV（挣值）、AC（实际成本）三条累计曲线放在一起。比较曲线的位置，可以判断进度偏差和成本偏差。

图：挣值分析三条曲线，看 EV 与 PV、AC 的相对位置

指标 公式 判断
CV 成本偏差 CV = EV − AC >0 节约，<0 超支
SV 进度偏差 SV = EV − PV >0 提前，<0 落后
CPI 成本绩效指数 CPI = EV / AC >1 节约，<1 超支
SPI 进度绩效指数 SPI = EV / PV >1 提前，<1 落后
ETC 完工尚需估算 ETC = (BAC − EV) / CPI 按当前绩效继续
EAC 完工估算 EAC = AC + ETC = BAC / CPI 典型偏差（偏差将持续）
VAC 完工偏差 VAC = BAC − EAC >0 节约，<0 超支
TCPI 完工尚需绩效指数 TCPI = (BAC − EV) / (BAC − AC) >1 难以完成，<1 较易完成

考点

  • EAC 有三种算法：非典型偏差 EAC = AC + (BAC − EV)；典型偏差 EAC = BAC / CPI；同时考虑进度 EAC = AC + (BAC − EV)/(CPI×SPI)。题目说“偏差不再发生/未来按计划”用第一种，说“偏差将持续”用第二种。
  • EV 用预算单价计算（PV 的完成比例），AC 是实际花费。
  • SV、CV 是绝对值，不能跨项目比较；SPI、CPI 是相对值，可以跨项目比较。
  • 计算题常与“预测完工日期”结合：预测工期 = 计划工期 / SPI。

五、质量管理类（图表密度最高的一章）

质量工具常按“老七种（基本工具）”和“新七种（管理工具）”整理。第三版教材正文还会按数据收集、数据分析、数据表现和决策等用途分类；历年题目中，两组工具也都出现过，案例题曾要求列出新七种工具。

老七种（基本质量工具） 新七种（质量管理和规划工具）
1. 因果图（鱼骨图/石川图） 1. 亲和图（KJ 法）
2. 流程图 2. 过程决策程序图（PDPC）
3. 核查表（计数表） 3. 关联图
4. 帕累托图 4. 树形图（系统图）
5. 直方图 5. 优先矩阵
6. 控制图 6. 活动网络图
7. 散点图 7. 矩阵图

分组依据：老七种工具多用于收集和分析数据、识别问题及观察分布；新七种工具侧重整理语言信息、梳理因素关系和辅助决策，常用于质量管理策划。

同一批工具在两个过程里的归属不同，这是真题的问法之一（“控制质量用到了哪些数据表现技术”）：

过程 数据表现技术 数据收集技术
管理质量 亲和图、因果图、流程图、直方图、矩阵图、散点图 核对单
控制质量 因果图、控制图、直方图、散点图 核对单、核查表、统计抽样、问卷调查

教材在管理质量与控制质量的工具清单中有不同安排：亲和图、流程图、矩阵图列在管理质量，控制图列在控制质量。帕累托图没有列入第三版这两处清单，但案例题仍会考查它的识别和用途，重点是找出造成多数问题的少数主要原因。

14. ① 因果图 / 鱼骨图 / 石川图（Cause-and-Effect Diagram）★★★

因果图将问题或结果放在“鱼头”位置，再按类别展开可能的原因，逐层分析原因之间的关系。它也叫石川图或鱼骨图。

图：因果图（鱼骨图），鱼头是问题，鱼骨是原因分类

  • 用途：找根本原因，用于“管理质量（质量保证）”过程，也用于缺陷分析。
  • 经典分类：人、机、料、法、环（4M1E），可根据行业调整（如加“测”）。
  • 常与“头脑风暴法”配合使用：先发散列出原因，再收敛找根因。

考点
题干出现“根本原因”“分析缺陷产生的原因”→ 因果图。注意与“关联图”区分：因果图是按类别结构化展开，关联图是自由连线展示复杂交织的因果关系。

15. ② 流程图（Flowchart）★★

流程图用标准符号表示开始与结束、处理、判断和输入输出，呈现过程的步骤顺序与分支，便于检查流程中的问题。

图：流程图，判断框分叉后汇合

  • 用途：理解过程、发现冗余环节、识别质量风险点；也用于“过程改进”。
  • 与“系统流程图/数据流图”不同：质量管理中的流程图强调过程步骤，可标注每个步骤的输入输出与责任人。
  • 是“新七种工具”中“活动网络图”的近亲，但活动网络图侧重活动先后依赖与工期。

考点
“用于分析过程中哪个环节出现问题”→ 流程图。软考常把“流程图”与“因果图”放在一起辨析：前者看过程，后者看原因。

16. ③ 核查表（Check Sheet，又称计数表）★

核查表是一种数据采集表格，用于在检查过程中记录缺陷类型、出现次数等信息，可为后续统计和绘图提供数据。

图：核查表，只记次数不做分析

  • 特点：只负责收集数据，不做分析；是“用数据说话”的第一步。
  • 教材原话：核查表又称计数表，用于合理排列各种事项，以便有效地收集关于潜在质量问题的有用数据。
  • 与“核对单（Checklist）”的区别：核对单是列好的清单，通过逐项列出检查点来核实步骤是否已执行，“反映该做的事情是否已做”，常被用作提醒（风险核对单、质量核对单）；核查表是计数工具，用来统计某类问题出现了多少次。教材里核对单又称“检查单”，与核查表（计数表）是两个东西，别按字面混。
  • 二者在教材中并列出现：控制质量的数据收集技术 = 核对单、核查表、统计抽样、问卷调查。

17. ④ 帕累托图（Pareto Chart）★★★

帕累托图将问题或缺陷按发生频次从高到低排列，并叠加累计百分比折线。它常与 80/20 法则联系起来，用于识别影响较大的少数问题或原因。

图：帕累托图 = 降序柱状图 + 累计百分比折线 + 80% 参考线

  • 用途：识别“少数关键问题”，确定质量改进的优先顺序，把有限资源投到最主要的缺陷上。
  • 关键特征：柱子必须按频次降序排列，否则不是帕累托图，只是普通直方图。
  • 理论上源自意大利经济学家帕累托，质量管理中由朱兰引入（“关键少数与次要多数”）。
  • 帕累托图不是用来显示“随时间变化”的，也不用于判断过程是否受控。
  • 第三版教材在管理质量和控制质量的数据表现技术清单中没有列出帕累托图，但案例题仍会考查。题目可能给出按频次降序排列的柱形和累计百分比折线，要求识别图形并说明用途。复习时应掌握图形特征和适用场景。

考点

  • 看到“80/20 法则”“确定优先解决顺序”“找出主要缺陷”→ 帕累托图。
  • 与直方图区别：帕累托图按频次降序 + 有累计线；直方图按数值区间排列，看分布形状。
  • 与因果图区别：因果图找原因，帕累托图找主要问题。
  • 判断题常见陷阱：“帕累托图用于描述集中趋势、分散程度和统计分布形状”——这是直方图的定义，错项。

18. ⑤ 直方图（Histogram）★★

直方图将连续数据按数值区间分组，以柱高表示各区间内的频次，用于观察数据分布，例如是否偏斜或呈现双峰。

图：直方图，看数据分布形态（是否正态、有无异常峰）

  • 用途：了解数据的分布情况与变异程度，判断过程能力是否满足要求。
  • 常见形态：正态型、偏态型、双峰型（可能混入两种不同来源的数据）、孤岛型（可能有异常数据）、平顶型。
  • 直方图不保留数据的时间顺序，因此不能像控制图那样用于观察过程随时间的变化。

考点
“显示数据分布频率、不涉及时间”→ 直方图。若题干强调“随时间变化的趋势/是否稳定”→ 控制图。

19. ⑥ 控制图（Control Chart）★★★

控制图按时间顺序记录数据，并标出中心线（CL）、上控制限（UCL）和下控制限（LCL），用于判断过程是否处于统计受控状态。

图：控制图，点落在上下控制限内且随机分布 = 过程受控

  • 判稳标准：所有点都在 UCL 与 LCL 之间，且点的排列随机、无规律。
  • 判异（失控）规则：①有点超出控制限；②连续 7 点在中心线同一侧；③连续 7 点持续上升或下降；④点呈明显规律性排列（周期性、趋势性）。
  • 控制限 ≠ 规格限：控制限由过程数据计算得出（±3σ），反映过程本身的能力；规格限由客户/合同规定，反映要求。
  • 用于“控制质量”过程，判断过程是否需要采取纠正措施。

考点

  • 七点规则（连续 7 点在中心线同侧即判失控）是高频数字。
  • 控制图只能判断过程是否稳定，不能判断产品是否合格——稳定不等于满足规格。
  • “质量特性值随时间变化的趋势”→ 控制图，而非直方图。

20. ⑦ 散点图（Scatter Diagram）★★

散点图将两个变量的成对观测值绘制成坐标点，用于观察两者之间是否存在相关性。

图：散点图的三种形态

  • 用途：研究两个变量之间的相关关系，例如“温度升高是否导致缺陷率上升”。
  • 相关性不能单独证明因果关系。散点图可以呈现变量之间的统计关联，无法仅凭图形确定因果方向。
  • 若需判断“某个原因是否真的影响结果”，可用实验设计（DOE）做验证。

考点
“研究两个变量之间的关系/相关性”→ 散点图。若题干说“确定哪个因素对结果影响最大”，则可能是实验设计或敏感性分析（龙卷风图）。

21. 新七种工具（1）：亲和图 / KJ 法（Affinity Diagram）★★

亲和图将收集到的意见、想法和文字信息按内容上的相似性分组，再整理成不同层次的类别，帮助归纳大量零散信息中的主题。

  • 由日本人川喜田二郎提出，故称 KJ 法。
  • 用于“质量管理策划”阶段，处理大量定性、无序的文字信息。
  • 典型场景：收集到 100 条客户抱怨，归并为 6 大类问题。

图：亲和图——散乱的卡片按亲和性聚成列，组名最后才起

考点
“把大量想法/意见按相似性归类整理”→ 亲和图。它不涉及数据分析，处理的是文字信息。

22. 新七种工具（2）：过程决策程序图（PDPC）★★

过程决策程序图（PDPC）用于计划阶段：预先列出实现目标时可能遇到的障碍，并为不同情况安排应对措施，形成多分支的行动方案。

  • 落点是预案思维：把风险应对前移到计划阶段。
  • 用于复杂计划的策划、重大问题的预防，属于质量管理策划工具。
  • 与流程图区别：流程图描述“正常路径”，PDPC 描述“出现偏差后的替代路径”。

图：PDPC——每遇到一个障碍就预先配一条对策，把风险应对前移到计划阶段

三条支路都要走到“目标达成”这一列，中间那条是主路径，上下两条是偏离后的替代路径。教材例题常把障碍写成“如果……”，把对策写成“则……”，读图时按这个句式替换即可。

23. 新七种工具（3）：关联图（Interrelationship Digraph）★★

关联图用箭头表示多个因素之间的影响方向。统计各因素的出箭头数（影响其他因素的程度）和入箭头数（受到其他因素影响的程度），可以帮助识别主要驱动因素和结果因素。

  • 适合处理因果关系错综复杂、相互交织的问题（原因与结果互为因果）。
  • 出箭头最多的因素是“驱动因素/根因”；入箭头最多的是“结果因素”。
  • 与因果图区别：因果图是预先设定类别（人机料法环）往下展开；关联图是自由连线，逻辑关系由参与者判断。

图：关联图——数箭头比看箭头重要，出多入少的是驱动因素

数箭头是这张图的用法：

节点 出箭头（影响力） 入箭头（被影响）
培训不足 2 0
标准不清 1 1
操作失误 1 2
检验不到位 1 0
缺陷率高 0 2

出多入少的是驱动因素，出 0 只进不出的是结果因素。这张图里培训不足出 2 入 0，是唯一的根因；缺陷率高出 0 入 2，是最终结果。考试给一张这样的图问“根本原因”，答案落在出箭头最多的节点上。

考点
“因素之间关系复杂、相互影响，需找出关键因素”→ 关联图。若题目明确“按人机料法环分类”→ 因果图。

24. 新七种工具（4）：树形图 / 系统图（Tree Diagram）★★

树形图将总目标或主题逐层拆分为子目标、子手段或组成部分，用于梳理实现目标所需的措施，也可展示一个问题包含哪些部分。

  • 结构上与 WBS 非常相似，但 WBS 分解的是“可交付成果”，树形图分解的是“目的—手段”或“因素”。
  • 常与亲和图配合：亲和图先归类，树形图再展开层次。
  • 可用于把大目标转化为可执行的具体措施。

图：树形图——分解的是目的与手段，最底层是可直接执行的动作

每一层都是“为了达成上一层的目标，需要做什么手段”，最底层是可直接执行的动作。WBS 的最底层是可交付成果（工作包），树形图的最底层是措施，这是两者的分界。

25. 新七种工具（5）：优先矩阵（Prioritization Matrix）★

优先矩阵按照一组加权标准为备选方案或事项评分，计算加权总分后进行排序，以确定处理优先级。

  • 就是一张打分排序表，用于方案选择、问题排序。
  • 与“矩阵图”区别：优先矩阵用于排序/择优，矩阵图用于分析两组因素之间的关系强度。

图：优先矩阵——权重 × 得分再逐列相加，按总分排序

算法是逐列加权求和：方案A = 0.4×3 + 0.3×4 + 0.2×2 + 0.1×3 = 3.0。权重之和应为 1，否则排序结果会被量纲拉偏。这套算法和加权评分法/多标准决策分析是同一个东西，只是在质量管理语境下叫优先矩阵。

26. 新七种工具（6）：活动网络图（Activity Network Diagram）★★

活动网络图以网络形式呈现任务之间的顺序与依赖关系，可据此识别关键路径，并调整任务之间的并行安排。

  • 形式上就是网络图（单代号/双代号），但在新七种工具语境下强调“优化活动顺序”。
  • 与“流程图”区别：流程图看过程步骤，活动网络图看并行任务与关键路径。
  • 与“PERT/CPM”是同一族方法。

图：活动网络图——采购与设计并行，两条路汇到测试

采购与设计可以并行，之后共同进入测试。图中持续时间最长的路径（立项→设计→编码→测试）是关键路径，它决定项目的最短完成时间。这里的“优化活动顺序”主要指调整活动之间的先后与并行关系；压缩单项活动的持续时间属于赶工。

27. 新七种工具（7）：矩阵图（Matrix Diagram）★★

矩阵图将两组或多组因素分别排列在行与列中，并在交叉位置用符号（◎、○、△、× 等）表示因素之间关系的强弱或有无。

教材按“能比较的因素组数”给出六种常用形态，这一条 24 年 11 月考过两批：

形态 表示的变量组数 关系结构
L 形 2 组 两组变量两两对应，最基本的矩阵
T 形 3 组 一组变量分别与另两组有关系，后两组之间无关系
Y 形 3 组 三组变量两两之间都有关系
X 形 4 组 每组变量同时与其他两组有关系
C 形 3 组 三组变量同时有关系（三维立方体视角）
屋顶形 1 组 同属一组的各个变量之间的关系

最常用的 L 形长这样，两组因素各占一轴，交叉格填关系符号：

图：矩阵图（L 形）——行列交叉处标关系强弱，形态按变量组数区分

  • 区分要点：Y 形和 C 形都是三组，区别在 Y 形是“两两之间”，C 形是“三组同时”；T 形也是三组，但有一对之间没有关系。
  • “屋顶形”就是质量屋的屋顶，单独用来表示技术特性彼此之间的相关性。
  • 典型应用：把“客户需求”与“技术特性”做交叉，就是质量屋（QFD）的核心矩阵。
  • 与“责任分配矩阵 RAM”结构相似，但目的不同：RAM 定职责，矩阵图分析关系强度。

28. 质量屋 / QFD 质量功能展开（House of Quality）★★

质量屋的外形类似房屋。它将客户需求（What）与技术特性（How）对应起来，再结合关系矩阵和竞争性评估，把客户需求转化为设计要求、零件特性和工艺要求。

图：质量屋的五个部位

结构说明：

部位 内容
左墙 客户需求（What）及权重
天花板 技术特性（How）
房间 关系矩阵，标注相关强弱（◎ 强 / ○ 中 / △ 弱）
屋顶 技术特性之间的相关性
右墙 / 地下室 竞争评估与目标值
  • 属于矩阵图的典型应用，是质量策划（规划质量管理）的重要工具。
  • 核心作用：确保技术方案真正响应客户需求。
  • 第三版教材在需求工程部分另有一处定义：质量功能部署（QFD）是“通过多种角度对产品的特点进行描述，从而反映产品功能”，是一种将用户要求转化成软件需求的技术，目的是最大限度提升软件工程过程中用户的满意度。这句是原话级的考点，两种问法都要认得。

考点
“把客户需求转化为技术/设计要求”→ 质量屋（QFD）。中项多以概念题形式出现，也可能考 QFD 的英文缩写与“将用户要求转化成软件需求”这句定义。

六、风险与决策类

风险管理工具常用于定性分析和定量分析。概率影响矩阵用于风险排序；决策树、龙卷风图、蒙特卡洛模拟和影响图可用于不同形式的定量分析。中项考试常考定性工具及决策树的 EMV 计算。

29. 风险分解结构（Risk Breakdown Structure, RBS）★★

风险分解结构按风险来源类别逐层整理风险，例如技术、管理、组织、外部和商务风险。识别风险时可以逐类检查，减少遗漏。

图：风险分解结构，按风险来源逐层分解

  • 典型一级分类：技术风险（需求、技术、性能）、管理风险（估算、计划、沟通）、组织风险（资源、资金、优先级）、外部风险（法规、市场、供应商）、商业/合同风险。
  • 作用：让风险识别更系统、更全面，也便于按类别汇总分析。

考点
资源分解结构（Resource BS）属于资源/成本管理，风险分解结构（Risk BS）属于风险管理。题干关键词“风险来源类别”vs“资源类别”。

30. 概率影响矩阵（Probability and Impact Matrix）★★★

概率影响矩阵以发生概率和影响程度为两个维度，将风险划分为高、中、低等等级，用于定性风险分析和优先级排序。

图：概率影响矩阵，红黄绿三区

纵轴的 0.9～0.1 是概率档位。档位怎么切、多少算高风险，由组织在规划风险管理时预先定义，不同项目可以不一样。

  • 用途：对识别出的风险做优先级排序，确定哪些需要重点应对、哪些只需列入观察清单。
  • 属于实施定性风险分析过程的核心工具。
  • 可分别针对成本、时间、范围、质量四个目标建立不同的矩阵。

考点
“对风险进行优先级排序/确定风险等级”→ 概率影响矩阵（定性分析）。若题干要求“量化风险对项目目标的影响数值”→ 定量分析（决策树、蒙特卡洛、敏感性分析）。

31. 风险登记册（Risk Register）★★★

风险登记册记录已识别风险及其相关信息，并随着风险识别、分析、应对和监控工作的推进而持续更新。

图：风险登记册的典型列

字段 说明
风险编号 / 类别 唯一标识，对应风险分解结构类别
风险描述 标准格式：原因 + 事件 + 影响（如“因供应商延期，导致设备到货推迟，影响联调进度”）
概率 / 影响 / 风险值 定性分析结果，用于排序
风险责任人（Owner） 每个风险必须有明确的责任人
应对策略与措施 规避、转移、减轻、接受（威胁）；开拓、分享、提高、接受（机会）
应急储备 / 弹回计划 应对成本与备用方案
状态 已识别 / 已分析 / 应对中 / 已关闭 / 已发生

考点
风险登记册在识别风险过程初步创建，在定性分析、定量分析、规划应对、实施应对、监督风险各过程中逐步更新完善。“风险责任人”与“风险应对责任人”必须明确到人。

32. 决策树（Decision Tree）★★★

决策树用分支表示决策方案、可能情形、发生概率和损益，并通过计算各方案的期望货币值（EMV）辅助比较方案。

图：决策树与 EMV 计算示例

  • 符号约定：方形 = 决策点（可选方案）；圆形 = 机会点/状态节点（概率分支）；三角形 = 结果（损益值）。
  • EMV = Σ(每种情形的概率 × 该情形的损益值)，若方案有前期投入，需再减去成本。
  • 属于实施定量风险分析的工具，也用于“自制或外购”“方案选择”等决策分析。
  • EMV 是“平均意义上的期望值”，不代表实际一定发生；它适用于重复性决策。

考点
计算题高频：给出概率和损益，求 EMV 并比较方案。注意三点：①别忘了减去投入成本；②概率之和必须为 1；③题目若问“应选择哪个方案”，选 EMV 最大的（对收益型决策）。

33. 龙卷风图 / 敏感性分析（Tornado Diagram）★★★

龙卷风图用横向条形表示各不确定因素对项目目标（如成本、工期）的影响幅度，并按幅度从大到小排列。它用于比较哪些因素对结果的影响更大。

图：龙卷风图，按影响幅度降序排列的敏感性分析结果

  • 敏感性分析：每次只改变一个变量，观察结果变化多少，从而找出“最敏感的变量”。
  • 龙卷风图是敏感性分析最直观的呈现形式，条形最长者即最关键风险。
  • 优点：简单直观、易沟通；缺点：一次只能看一个变量，无法反映变量之间的相互作用（这是与蒙特卡洛模拟的关键区别）。

考点

  • “确定哪些风险因素对项目影响最大”→ 敏感性分析（龙卷风图）。
  • 敏感性分析通常逐次改变一个变量，难以呈现多个变量同时变化及其相互作用。
  • 属于定量风险分析工具。

34. 蒙特卡洛模拟（Monte Carlo Simulation）★★

蒙特卡洛模拟通过计算机对多个不确定变量进行大量随机抽样，每次计算得到一组结果，最终形成项目总成本或总工期的概率分布。

图：蒙特卡洛模拟，看分布而不是单点

  • 输出：累计概率分布曲线（S 曲线形态），可回答“项目在 X 天内完工的概率是 85%”这类问题。
  • 能反映多个变量的综合作用与相关性，比敏感性分析更全面、更接近现实。
  • 缺点：依赖模型与历史数据的准确性，计算量大，成本较高。

考点
“通过多次模拟得到项目完工概率分布”→ 蒙特卡洛。区分：敏感性分析看单个变量，蒙特卡洛看综合概率分布。

35. 影响图（Influence Diagram）★

影响图用节点和箭头表示变量之间的影响关系及决策顺序，可用于梳理复杂决策问题中的变量、决策和结果。

图：影响图，方框是决策，椭圆是不确定因素

  • 节点类型：决策节点、不确定性节点、价值/目标节点。
  • 作用：先理清“哪些因素影响哪些结果”，再决定是否需要用决策树做定量计算。
  • 属于定量风险分析的工具之一，中项考试多以概念辨析出现。

七、干系人与沟通类

这部分主要涉及干系人管理和沟通管理。权力/利益方格用于制定干系人管理策略，沟通渠道公式用于计算沟通路径数量。

36. 权力 / 利益方格（Power / Interest Grid）★★★

权力/利益方格以权力（影响力）为纵轴、利益（关注度）为横轴，将干系人划分为四个象限，并据此安排不同的管理策略。

图：权力利益方格与四种策略

  • 高权力 + 高利益（关键决策者、核心客户）：重点管理——密切沟通、主动征求意见、确保满意。
  • 高权力 + 低利益（上级领导、监管部门）：令其满意——保证其关注点得到满足，不必过度打扰。
  • 低权力 + 高利益（一线使用者、项目组成员）：随时告知——及时通报进展，避免因信息不对称引发抵触。
  • 低权力 + 低利益（外围相关方）：监督——花最少精力，定期简单通报即可。

考点
四象限策略是高频考点。此外还有“权力/影响方格”“影响/作用方格”“凸显模型”（按权力、紧迫性、合法性三个维度分类），题干出现“紧迫性+合法性”→ 凸显模型。

37. 干系人参与评估矩阵（Stakeholder Engagement Assessment Matrix）★★★

干系人参与评估矩阵并列记录当前参与水平（C）和期望参与水平（D），用两者的差距确定后续参与管理的重点。

图：干系人参与评估矩阵，C 是现状 D 是目标

- **五种参与水平**：不知晓 → 抵制 → 中立 → 支持 → 领导（由低到高）。 - **C = Current（当前）**，**D = Desired（期望）**。差距越大，越需要投入沟通资源。 - 属于“**规划干系人参与**”过程的工具，输出干系人参与计划。

考点
五级水平的名称与顺序；C/D 的含义；“通过沟通使干系人从抵制转为支持”正是该矩阵的应用场景。

38. 沟通模型（Communication Model）★★

沟通模型描述信息从发送者到接收者的传递过程：编码 → 媒介（渠道）→ 解码。传递过程可能受到噪声干扰，因此需要接收者确认理解，并通过反馈检查沟通效果。

图：沟通模型五要素 + 噪声 + 反馈

  • 五要素：发送者、编码、媒介、解码、接收者。加上噪声和反馈构成完整模型。
  • 判断沟通是否完成，要看接收方是否理解信息。信息发出后仍需通过确认和反馈检查理解情况。
  • 沟通渠道数 = N(N−1)/2（N 为干系人/沟通参与人数）。
  • 沟通方式三类：交互式（会议、电话，效率最高）、推式（邮件、报告，主动推送）、拉式（知识库、内网，接收者自取）。

考点

  • 沟通渠道计算题高频：如 10 人团队，渠道数 = 10×9/2 = 45；新增 2 人后 = 12×11/2 = 66，增加 21 条。
  • “有效沟通的关键是理解”；“沟通中最重要的是反馈”。
  • 90% 的项目经理时间用于沟通——常见常识型选项。

八、采购、配置与组织类

这部分内容容易在复习时被略过，但考试选择题会涉及，尤其要区分组织结构类型、合同类型的风险分配和配置项状态。

39. 组织结构类型图（Organizational Structure）★★★

组织结构图展示项目团队在组织中的位置和汇报关系，常见类型包括职能型、项目型、矩阵型（弱矩阵、平衡矩阵、强矩阵）以及 PMO 型。

图：三种组织结构里 PM 的权力差异

类型 项目经理权力 可用资源 预算控制者 项目成员归属
职能型 很小 / 无 很少 职能经理 按职能划分，兼职
弱矩阵 小 有限 职能经理 兼职，协调员角色
平衡矩阵 中 中等 职能经理与 PM 共享 兼职
强矩阵 较大 较大 项目经理 专职
项目型 很大 / 全部 几乎全部 项目经理 专职，独立团队
PMO 型 最大（PMO 直接管理） 全部 PMO 专职

考点
PM 权力由小到大：职能型 < 弱矩阵 < 平衡矩阵 < 强矩阵 < 项目型 < PMO。题目常问“项目经理权限最大的是哪种组织”——答：项目型（或 PMO 型，视选项而定）。

40. 合同类型与风险分配（Contract Types）★★★

按计价方式，合同常分为总价合同、成本补偿合同和工料合同。不同类型的合同会将成本超支风险以不同方式分配给买方和卖方。

图：合同类型与风险分配（从左到右：买方风险递减、卖方风险递增）

缩写 全称 成本风险主要落在
CPPC 成本加成本百分比 买方（多数国家已禁用）
CPFF 成本加固定费用 买方
CPIF 成本加激励费用 买方为主，双方共担部分
T&M 工料合同 双方分担（买方担工作量，卖方担单价）
FPIF 总价加激励费用 卖方为主，有价格上限
FFP 固定总价 卖方
  • 总价合同：固定总价 FFP、总价加激励费 FPIF、总价加经济价格调整 FP-EPA。适用于需求明确、范围清楚的项目。
  • 成本补偿合同：CPFF、CPIF、CPAF。适用于范围不明确、需要快速启动、研发型项目。买方承担成本风险。
  • 工料合同：按工时/材料单价结算，适合规模小、工期短、金额不大、范围不清的补充性工作。

考点
“买方风险最大/最不利于买方”→ CPPC（成本加成本百分比，多数国家已禁用）；“卖方风险最大”→ 固定总价（FFP）；“范围不明确时应选”→ 成本补偿合同或工料合同。

41. 配置项状态图（Configuration Item Status）★★

配置项状态图展示配置项在配置管理中的状态变化，例如草稿 → 正式（受控）→ 修改。状态变更应经过相应的变更控制流程。

图：配置项三态流转

  • 配置管理五大活动：配置管理计划 → 配置识别 → 配置控制（变更控制）→ 配置状态报告 → 配置审计（功能配置审计 FCA + 物理配置审计 PCA）。
  • 基线：经过正式评审批准的配置项集合，是后续变更的比较基准。常见基线：功能基线、分配基线、产品基线（或需求/设计/产品基线）。
  • 配置审计：FCA 验证“功能是否实现、是否满足需求”；PCA 验证“实际交付物与配置文档是否一致”。

考点
配置项三种状态（草稿/正式/修改）；基线一经建立，变更必须走变更控制流程（CCB 审批）；配置审计分 FCA 与 PCA。

42. PDCA 循环（戴明环，PDCA Cycle）★★

PDCA 循环包括 Plan（计划）→ Do（执行）→ Check（检查）→ Act（处理/改进），用于持续检查工作结果并改进后续过程。

图：PDCA 循环

  • 对应质量管理过程：规划质量管理（P）→ 管理质量（D）→ 控制质量（C）→ 质量改进（A）。
  • 管理质量（质量保证）偏“过程”，关注过程是否合规；控制质量偏“结果”，关注可交付成果是否合格。
  • 质量改进常用工具：PDCA、六西格玛（DMAIC）、质量审计、根本原因分析。

考点
“管理质量”对应质量保证（过程导向，防止缺陷产生）；“控制质量”对应检查（成果导向，发现缺陷）。两者顺序：先保证过程，再检查结果。

43. 项目生命周期与资源投入曲线（Project Life Cycle）★★

项目生命周期图以项目阶段为横轴、成本与人力投入水平为纵轴。资源投入通常呈中间高、两端低的趋势；风险与不确定性一般随项目推进而下降，变更成本则通常逐渐上升。

图：三条曲线反向——投入中间高，风险前高后低，变更代价前低后高

  • 项目初期：风险与不确定性最高，变更代价最低；项目末期相反。
  • 这一规律是“尽早识别风险、尽早确认需求”的理论依据。
  • 预测型生命周期（瀑布）vs 迭代型/增量型 vs 适应型（敏捷）：变更成本曲线的形态不同。

考点
“在项目哪个阶段变更代价最大”→ 收尾阶段；“风险最高”→ 启动/概念阶段。这是选择题的固定考点。

44. 软件工程类图形（DFD / ERD / State Diagram）★★

这类图属于软件工程技术基础内容，虽然不在项目管理工具的主体范围内，也可能出现在中项考试的技术基础题中。

图：DFD / ERD / 状态图各一例

  • 数据流图 DFD：四种元素——外部实体（方框）、处理过程（圆/圆角框）、数据存储（开口矩形/双横线）、数据流（箭头）。用于结构化需求分析，分顶层图、0 层图、1 层图逐层细化。
  • ER 图（实体—联系图）：实体（矩形）、属性（椭圆）、联系（菱形），标注 1:1、1:N、M:N 三种联系类型。用于数据库概念设计。
  • 状态转换图：圆形表示状态、箭头表示转换事件，用于描述对象在生命周期内的状态变化（如订单：待支付→已支付→已发货→已完成）。
  • 系统流程图：描述系统中各部件之间数据流动的物理模型。

考点
DFD 的四种元素及其图形符号；ER 图中“菱形”表示联系；分层数据流图需保持父图与子图平衡（输入输出数据流一致）。

十、考前自测清单

复习时可以逐项检查：能否说明每种工具的用途、适用场景，以及它与相似工具的区别。

  • WBS 分解的对象是可交付成果，遵循 100% 原则，最底层是工作包（8～80 小时）
  • WBS、OBS、RAM 三者关系：做什么 / 谁来做 / 谁负责什么
  • RACI 中 A 有且只有一个
  • 需求跟踪矩阵实现双向追溯，防止需求遗漏与范围蔓延
  • 甘特图不能反映逻辑依赖与关键路径
  • 里程碑工期为 0，用于高层汇报
  • 单代号（节点=活动）与双代号（箭线=活动）的区别；虚活动工期为 0、不耗资源
  • 关键路径是最长路径，总浮动时间为 0，可能不止一条
  • TF = LS − ES = LF − EF；自由浮动 = min(紧后 ES) − 本活动 EF
  • 时标网络图中无波形线的路径即关键路径
  • 资源平滑不延长工期，资源平衡可能延长工期
  • 成本基准不含管理储备，总预算 = 成本基准 + 管理储备
  • 应急储备应对“已知—未知”，管理储备应对“未知—未知”
  • EV 在分子：CV = EV − AC，SV = EV − PV，CPI = EV/AC，SPI = EV/PV
  • EAC 三种算法及适用条件（非典型 / 典型 / 兼顾进度）
  • 老七种、新七种各七个，能完整列出
  • 矩阵图六种形态按变量组数分：L 形 2 组、T/Y/C 形各 3 组（T 形有一对无关系、Y 形两两相关、C 形三组同时相关）、X 形 4 组、屋顶形 1 组
  • 管理质量的数据表现技术 vs 控制质量的数据表现技术，两份清单的差别在哪
  • 核对单（检查单）vs 核查表（计数表）不是一回事
  • 帕累托图 = 降序柱状图 + 累计折线，80/20 法则，找主要问题
  • 因果图找根本原因；散点图看相关性（相关≠因果）
  • 控制图七点规则；控制限 ≠ 规格限；控制图只判稳定不判合格
  • 质量屋（QFD）把客户需求转化为技术特性；QFD 的定义是“将用户要求转化成软件需求的技术”
  • 两个 RBS 的区别（资源 vs 风险）
  • 概率影响矩阵用于定性分析排序；决策树、蒙特卡洛、敏感性分析用于定量分析
  • 决策树 EMV = Σ(概率×损益) − 投入成本，选 EMV 最大者
  • 龙卷风图 = 敏感性分析，不能反映变量间相互作用
  • 权力/利益四象限策略；凸显模型三维度（权力、紧迫性、合法性）
  • 干系人参与五级：不知晓→抵制→中立→支持→领导
  • 沟通渠道 = N(N−1)/2；沟通完成的标志是被理解
  • 组织结构 PM 权力排序；合同类型风险分配
  • 配置项三态：草稿→正式→修改；FCA 与 PCA 的区别
  • 项目初期风险最高、变更代价最低；收尾阶段变更代价最高
